# 機能一覧と、今回作らないもの

チームチャットアプリの機能を、仕様書（`docs/spec.md`）とモックアップ（`mockup/`）から洗い出し、確認事項の回答・決定（`questions.md`）を反映したものです。

- 機能は **F-01** から連番です。「確認・回答」の欄には、関連する確認事項（**Q-xx**）と、クライアントの回答（**R-xx**）の番号を書いています。回答と決定の中身は、`questions.md` にあります
- 「内容」の欄は、確認事項の回答・決定を反映した、**いま決まっている内容**です。**Q-19 だけは保留**で、決まっていません（F-16、F-17）
- 「根拠」の `spec` は仕様書の章番号、`mock` はモックアップのファイル名、`guide` は `mockup/design-guide.md` の章です
- 根拠が **mock のみ**の項目は、仕様書に文章がなく、モックアップにだけ描かれているものです。仕様書 5-3 の「モックアップが正」に従って機能に入れています

## 2. 今回作らないもの

### 2-1. 仕様書が「作らない」と明記しているもの

| 作らないもの | 理由（仕様書 4 のまま） | 根拠 |
|:--|:--|:--|
| 新着メッセージの自動表示（画面を開いたままで届く） | 今回は画面を開き直して確認できれば十分 | spec 4 |
| 通知（メール・スマートフォンへの通知） | まずは社内で使い始められる形を優先したい | spec 4 |
| 1対1のダイレクトメッセージ | チャンネルでの会話に絞りたい | spec 4 |
| ファイル・画像の添付 | 文章のやり取りに絞りたい | spec 4 |
| メッセージへのリアクション（絵文字を付ける） | 会話ができることを優先したい | spec 4 |
| 未読・既読の管理 | 同上 | spec 4 |
| 管理者による全体管理（利用者の停止、他人のチャンネルの管理） | 運用が固まってから考えたい | spec 4 |

| チャンネルを作った人の、別の人への交代 | クライアントの回答（今回は交代できなくてよい） | R-04 |

### 2-4. 確認事項にしていないが、作らない想定のもの

確認事項には挙げておらず、モックアップに描かれていないための想定です。

| 作らない想定のもの | 想定の理由 |
|:--|:--|
| 検索の絞り込み（期間・チャンネル・投稿者の指定） | 検索画面の見本が、キーワードの入力欄だけ（mock search） |
