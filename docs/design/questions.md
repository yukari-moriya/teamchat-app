# 確認事項リスト

仕様書（`docs/spec.md`）とモックアップ（`mockup/`）を読んで、**書かれていなかったこと・食い違っていたこと**をまとめたものです。仕様書 6 の「自分で決めずに、想定を添えて質問する」に従い、どの項目も**こちらの想定**を添えています。

- 番号は **Q-01** から連番です。関連する機能は `features.md` の ID（F-xx）で示しています
- 「優先度」は、答え次第でどれだけ設計が変わるかです。**高**＝画面・データ・権限の作りが変わる／**中**＝画面の細部や挙動が変わる／**低**＝ほぼ想定どおりで進められる
- 「状態」の欄は、クライアントの回答の受け取り状況です。**回答済み**＝聞いたことに答えが返ってきた／**一部回答**＝聞いたことの一部にだけ答えが返ってきた（返ってきていない部分は「11. Qごとの回答状況」に書いた）／**回答なし**＝回答が返ってきていない（設計側で決めるまで、そのままにしている）／**設計側で決定**＝回答が返ってこなかったので、設計側で決めた（「13. 自分で決めたこと」に書いた。クライアントの回答ではない）
- 返ってきた回答は「10. 返ってきた回答（原文）」に、もらったまま載せ、どのQに当たるかを対応づけた（R-01〜R-13）。どのQにも当たらなかった回答は「12.」に残してある
- 決まったことを設計に反映するときは、あわせて該当の設計書も直します
- 根拠の `spec` は仕様書の章、`mock` はモックアップのファイル、`guide` は `mockup/design-guide.md` の章です
