# 権限・ルーティング・公開API（権限マトリクス・ルーティング一覧・公開APIの設計）

仕様書（`docs/spec.md`）・モックアップ（`mockup/`）・ここまでの設計書（`features.md`・`questions.md`・`screens.md`・`data.md`）を根拠に、誰が何をできるか、どのURLで受けるか、公開APIが何を返すかを決めたものです。

- 機能は `features.md` の **F-xx**、確認事項と決定は `questions.md` の **Q-xx**／**R-xx**／**D-xx**、画面は `screens.md` の **SC-xx** で示します
- 根拠の資料に無く、ここで選んだものには **［設計］** を付けています
- **根拠が無く、選び方で作りが変わるものは、埋めずに「4. まだ決まっていないこと」に書いています**
- 例外が起きたときの扱いの全体は `behavior.md` の「3. 例外方針」にあります。ここでは権限とAPIに関わる分だけを書きます

## 1. 権限マトリクス

### 1-1. 列（利用者の区分）

| 列 | 誰か |

| 未ログインの人 | ログインしていない人。公開APIを呼ぶ別の仕組み（社内ポータル）も、ここに入る |

### 1-3. △の条件

| 記号 | 条件 | 根拠 |

### 1-4. 表の形に入らないもの（検索と公開API）

1-2 の表は、**機能の入口**で「誰が使えるか」を分けたものです。検索と公開APIにも○△×を付けていますが、この2つで守りたいことは入口では決まりません。**表の欄が埋まっていても、この2つが守れているとは言えません。**

**表の形に入らない理由**

| 機能 | 表で分かること | 表では分からないこと |
|:--|:--|:--|
| 検索（F-21・F-22） | ログインしていれば使える（R-09） | **結果に何が混ざるか**。検索は1つのチャンネルの中ではなく、すべてのチャンネルのメッセージをまとめて探す。入口が ○ でも、結果の1件ずつについて「見られるチャンネルのものか」「削除されていないか」を見なければ、見られないプライベートチャンネルや、消したメッセージの本文が出る。同じ人でも、メンバーから外されると見られる範囲が変わる（Q-10） |
| 公開API（F-23・F-24） | 誰でも呼べる | 呼んだのが誰かを見ないので、列の区分（社員・作成者）に意味が無く、3列とも同じ △ e になる。守っているのは「誰が呼んだか」ではなく、**返すデータの範囲**。プライベートチャンネルのメンバーが呼んでも、そのチャンネルは返さない |

**どう守るか**

| 機能 | 漏れる出口 | 守り方 | 根拠 |
|:--|:--|:--|:--|
| 検索 | 結果の行・件数（「◯件」）・ページ送り | 見られるチャンネルの絞り込みと、削除済みを除く条件を、**検索の問い合わせそのもの**に入れる。取ってきたあとに画面で間引くことはしない（件数やページ送りの数が合わなくなり、見えない結果があることが分かってしまうため）。どちらの条件も、1-6 の1か所にまとめたものを通す | spec 3-6 / F-21 / Q-10 / D-05 のリスク2 |
| 公開API | 一覧の行・404 の本文の違い・ブラウザからの直接の呼び出し | 公開チャンネルだけの絞り込みと、削除済みを除く条件を1か所にまとめ、2つのAPIで同じものを通す。404 は理由を問わず同じ本文にする（3-4）。CORS の許可は出さない（3-1） | spec 3-7 / R-11 / Q-27 / D-05 のリスク3 |
| 両方 | 確かめ方 | 表の○×では確かめない。受け入れ条件（`acceptance.md`）に、検索と公開APIのそれぞれで「見られないプライベートチャンネルの内容が出ない」「削除したメッセージが出ない」を、別々の行として置く | D-05 の補足（リスクと手当て） |

| 場面 | 返し方 | 根拠 |
|:--|:--|:--|
| 未ログインの人が、画面のURLを開く・送信する | SC-01（ログイン）へ移す | F-04 / Q-04 |
| ログインしている人が、SC-01・SC-02 を開く・送信する | SC-03（チャンネル一覧）へ移す［設計］ | screens.md の画面一覧（使える人は未ログインの人）/ Q-04 |
| 存在しないチャンネル・**見られないプライベートチャンネル**のURLを開く・送信する | **どちらも同じ 404**（SC-10） | R-01 / Q-06 / screens.md SC-10 |
| 公開チャンネルのメンバー管理（SC-08）のURLを開く・送信する | 404（その画面が無い）。**作成者かどうかに関わらず**、公開チャンネルかどうかを先に見る | F-11 / D-23 |
| 見られるチャンネルで、作成者でない人が編集・削除・メンバー管理（プライベートチャンネルのとき）のURLを開く・送信する | **403**（Laravel の標準の画面。英語のまま。D-14） | D-15 |
| 他人のメッセージ・削除済みのメッセージを、編集・削除しようとする（画面には操作を出さないので、直接送られたとき） | **403** | D-15 / D-05 のリスク4 |

| 公開APIで、存在しないID・プライベートチャンネルのIDを指定する | **どちらも同じ 404、同じ本文**（3-4） | Q-27 |

### 1-6. どこで確かめるか

権限の確かめは、Laravel の標準の部品に置きます［設計］。ポリシーが拒否したときは、チャンネルを見られない（`view`）ときの 404 を除いて、403 を返します（D-15）。

| 確かめること | どこで | 根拠 |
|:--|:--|:--|
| ログインしているか | `auth` ミドルウェア（未ログインなら SC-01 へ） | F-04 |
| ログインしていないか | `guest` ミドルウェア（ログイン中なら SC-03 へ。移す先の既定値 `RouteServiceProvider::HOME` は `/home` なので `/channels` に変える） | 1-5 |
| ログインの試行回数 | Fortify の `LoginRateLimiter`（`RateLimiter` を使う）を継いで使う。メールアドレスのそろえた写しと IP の組ごとに1分5回まで。超えたら SC-01 にエラーを出す（screens.md 4-2） | D-28 |
| チャンネルを見られるか（a） | `ChannelPolicy` の `view`。見られないときは `Response::denyAsNotFound()` で **404** にする | R-01 |
| チャンネルを作った人か | `ChannelPolicy` の `update`・`delete` | spec 3-2 |
| メンバーを管理できるか（c） | `ChannelPolicy` の `manageMembers`（作った人で、プライベート）。**先に公開チャンネルかどうかを見て**、公開なら作った人でも 404。プライベートで作った人でなければ 403 | spec 3-3 / F-11 / D-23 |
| 自分が書いた・削除されていないか（b） | `MessagePolicy` の `update`・`delete`。その前に `ChannelPolicy` の `view` で、チャンネルを見られるかを確かめる（見られなければ 404。D-16） | spec 3-4 / D-05 / D-16 |
| URLのメッセージ・メンバーが、URLのチャンネルのものか | ルートの `scopeBindings()`。違えば 404 | R-01（別のチャンネルのIDで、見えないチャンネルの中身に触れないため） |
| サイドバー・一覧・検索・チャンネル名の重複チェックを、見られるチャンネルに絞る | **Channel モデルの1つのスコープにまとめ、すべてそこを通す** | spec 3-6（特に強く求められている）/ Q-32 |
| 公開APIを、公開チャンネル・削除されていないメッセージに絞る | 公開チャンネルの絞り込みを1つのスコープに、削除済みを除く条件を1か所にまとめる | spec 3-7 / D-05 のリスク2・3 |

## 2. ルーティング一覧

### 2-1. 画面（web）

### 2-2. 画面の状態のURL

JavaScript を使わない（D-03）ので、SC-04・SC-05・SC-07・SC-09 の中の状態は、URLのクエリで区別します。screens.md 2-2 の状態に対応します［設計］。

| 状態 | URL | 例 |
|:--|:--|:--|
| SC-04 チャンネル（通常） | `/channels/{channel}` | `/channels/2` |
| SC-04 メッセージを編集中 | `/channels/{channel}?edit={message}` | `/channels/2?edit=18` |
| SC-05 スレッドを開いている | `/channels/{channel}?thread={message}` | `/channels/2?thread=14` |
| SC-05 返信を編集中 | `/channels/{channel}?thread={message}&edit={返信}` | `/channels/2?thread=14&edit=21` |
| SC-04 を編集中で、SC-05 も開いている | `/channels/{channel}?thread={message}&edit={message}` | `/channels/2?thread=11&edit=18` |
| SC-07 削除の確認を開いている | `/channels/{channel}/edit?confirm_delete=1` | `/channels/2/edit?confirm_delete=1` |
| SC-09 結果を出している | `/search?q={キーワード}&page={ページ}` | `/search?q=リリース` |

**クエリの決まり**

| クエリ | 決まり | 根拠 |
|:--|:--|:--|
| `thread` | そのチャンネルの、返信でないメッセージのID。削除されたメッセージでもよい。**そのチャンネルに無いID・返信のIDは 404** | F-18 / R-01（別のチャンネルのIDで中身が出ないように）/ R-08 |
| `edit` | そのチャンネルのメッセージ・返信のID。返信のときは `thread` がその返信の元と同じであること（`thread` が無い・元と違うときは、編集中にせず通常の表示にする。`thread` が正しいIDなら、そのスレッドは開く。D-26）。**そのチャンネルに無いIDは 404**。あっても b を満たさない（他人の・削除済み）ときは、編集中にせず通常の表示にする［設計］ | F-16 / R-01 / D-26 |
| `confirm_delete` | `1` のとき確認を開く。それ以外は無視 | screens.md SC-07 |
| `q` | **`q` が無い**ときは入力欄だけを出す。**`q` があって空**（前後の空白を取り除いて空）のときは、SC-09 の入力欄の下にエラーを出す（元の画面へは戻さない。上部バーから送ったときも SC-09 に出す）［設計］ | screens.md SC-09 / D-02 |
| `page` | 検索結果のページ（1ページ20件）。無ければ1 | Q-21 |
| ほかのクエリ | 無視 | ［設計］ |

**操作したあとの位置**

送信・保存・削除のあとは、その行の位置まで移動した状態で見せます（screens.md 2-2）。位置は、URLの `#` で指します［設計］。

- SC-04 のメッセージの行には `id="message-{id}"`、SC-05 の返信の行には `id="reply-{id}"` を付ける（スレッドの元のメッセージは SC-04 と同じ行が2つ並ぶので、パネル側には付けない）
- SC-04・SC-05 のフォームは、開いているスレッドのIDを `thread` として一緒に送る。戻り先は `/channels/{channel}`（`thread` があれば `?thread=` を付ける）＋`#message-{id}` または `#reply-{id}`。`edit` は付けない（保存したら通常の状態へ）
- 入力エラーのときは、送った画面（編集中ならその状態のURL）に戻す（D-02）
- 検索結果の行のリンク（F-22）も同じ形: チャンネルのメッセージなら `/channels/{channel}#message-{id}`、返信なら `/channels/{channel}?thread={元}#reply-{id}`（Q-22）

### 2-3. フォームが送る項目

| No | 送り先 | 送る項目 |

## 3. 公開APIの設計

### 3-1. 共通

| 項目 | 決めたこと | 根拠 |
|:--|:--|:--|
| 認証 | なし（ログインもトークンも要らない） | spec 3-7 |
| 使えるメソッド | GET だけ。書き込み・変更のAPIは作らない | spec 3-7 |
| 呼ぶ側 | 社内ポータルの**サーバー**。ブラウザから直接は呼ばない。**ブラウザ向けの許可（CORS）は出さない**（Laravel の既定の `config/cors.php` は `api/*` をどこからでも許すので、`api/*` を外す） | Q-27 |
| 返す形 | いつも JSON（`Content-Type: application/json`）。呼ぶ側が `Accept` を付けなくても、エラーも JSON で返す［設計］ | ［設計］ |
| 日時 | 日本時間で、ISO 8601 の時差つきの形（`2026-08-17T09:12:00+09:00`）［設計］ | Q-31 |
| 返さないもの | プライベートチャンネルのすべて（名前も）、削除されたメッセージ、メールアドレスなど個人を特定できる情報、返信の中身 | spec 3-7 / R-11 / Q-24 / Q-23 |
| 項目名 | 英字の小文字とアンダースコア［設計］ | ［設計］ |

- 例のIDと、チャンネルの作成日時は、例のための値（初期データの決まりではない）

### 3-3. GET /api/channels/{channel}/messages（公開チャンネルのメッセージの一覧。F-24）

**入力**

| 場所 | 名前 | 必須 | 中身 |
|:--|:--|:--|:--|
| パス | `{channel}` | ○ | 公開チャンネルのID（3-2 の `id`） |
| クエリ | `cursor` | | 続きを取るときに、前の返事の `meta.next_cursor` をそのまま入れる。無ければ最初（いちばん新しいもの）から |

**出力**: 200。**チャンネルに直接書かれたメッセージだけ**を、**新しい順**に、1回に**最大50件**（Q-23、Q-26）。削除されたメッセージは**行ごと入れない**（R-11）。

| 項目 | 型 | 中身 | 根拠 |
|:--|:--|:--|:--|
| `data[].id` | 整数 | メッセージのID | Q-24 |
| `data[].body` | 文字列 | 本文（書いたまま。改行は `\n`） | Q-24 / Q-13 |
| `data[].author_name` | 文字列 | 投稿者の表示名 | Q-24 |
| `data[].created_at` | 文字列（日時） | 投稿日時 | Q-24 |
| `data[].is_edited` | 真偽 | 編集済みか | Q-24 / D-09 |
| `data[].reply_count` | 整数 | 返信の件数。**削除された返信も数える** | Q-24 / D-05 |
| `links.next` | 文字列または null | 続きを取るURL。続きが無ければ null | Q-26 |
| `meta.next_cursor` | 文字列または null | 続きを取るときの `cursor` の値。続きが無ければ null | Q-26 |
| `meta.per_page` | 整数 | 1回の最大件数（50） | Q-26 |

### 3-4. エラーの返し方

エラーはどれも、本文を `{"message": "…"}` の形の JSON にします［設計］。

| ステータス | いつ | 本文 | 根拠 |
|:--|:--|:--|:--|
| 404 | `{channel}` が、**存在しないID・プライベートチャンネルのID・数字でないもの**のとき。`/api/` の下の、無いURLのとき | **いつも** `{"message": "Not Found"}` | Q-27 |
| 405 | GET 以外で呼ばれたとき | `{"message": "Method Not Allowed"}` | spec 3-7 |
| 429 | 呼ぶ回数の上限を超えたとき（呼ぶ側のIPごとに1分60回。Laravel の既定のまま） | `{"message": "Too Many Attempts."}` | D-18 |
| 500 | 想定外の失敗（データベースにつながらない、など） | `{"message": "Server Error"}`（中身の詳しいことは出さない） | `behavior.md` 3章 |

**404 の本文を固定する理由**: Laravel の既定のままだと、存在しないIDのときは「`No query results for model [App\Models\Channel] 9`」のようにモデルの名前とIDを含む文が、プライベートチャンネルのときに自分で 404 を返すと別の文が返る。**本文の違いから、そのIDにプライベートチャンネルがあることが分かってしまう**（Q-27 の「返事の違いから分からないように」に反する）。そのため、404 は理由を問わず同じ本文にする。

**例**: プライベートの「採用プロジェクト」（ID 4）を指定しても、存在しない ID 999 を指定しても、同じ返事になる。

```text
GET /api/channels/4/messages     → 404 {"message": "Not Found"}
GET /api/channels/999/messages   → 404 {"message": "Not Found"}
```
