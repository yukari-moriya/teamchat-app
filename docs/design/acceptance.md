# 受け入れ条件とテスト観点

仕様書（`docs/spec.md`）・モックアップ（`mockup/`）・ここまでの設計書（`features.md`・`questions.md`・`screens.md`・`data.md`・`permissions-api.md`・`behavior.md`）を根拠に、できあがったものを何で確かめるかを決めたものです。

- 機能は `features.md` の **F-xx**、確認事項と決定は `questions.md` の **Q-xx**／**R-xx**／**D-xx**、画面は `screens.md` の **SC-xx** で示します
- **受け入れ条件**（1章）は、人がブラウザで手で試し、1行ずつ合否を付けるためのものです。1つの実装単位につき2〜4行にとどめています。番号は `AC-<実装単位の番号>-<連番>` で、実装単位の番号は 1 認証／2 チャンネル／3 メンバー管理／4 メッセージ／5 スレッド／6 検索／7 公開API です
- **テスト観点**（2章）は、テストコードで網羅するときの観点です。観点だけを書き、組み合わせは書き出していません。番号は `TP-<実装単位の番号>-<連番>` で、7つの実装単位に入らないもの（初期データ・画面に共通する例外）は `TP-8-xx`（共通）にまとめています
- 入力チェック（F-25）は、その欄がある画面の実装単位に振り分けています
